# Brand Engine Guidelines for AI Assistants

Rules for AI assistants (Claude Code, Cursor, etc.) and humans creating content in this repo.

**Everything about the creator comes from their own files. Read these before writing anything:**
- `config.yaml` -> `person` (name, handle, links) and `niche` (topic, angle, audience, pillars, voice,
  keywords, hashtags, call to action, rules)
- `data/brand_brief.md` -> every verified fact (F001...) the writer may state (generated by `python cli.py ingest`)
- `data/voice_samples.md` -> the creator's own past posts: match this voice

Never hardcode identity or niche in code, decks or captions; read it from these files.

## 1. Content rules
- **Grounded only:** state facts about the creator only if they appear in `data/brand_brief.md`. Never invent numbers, results, clients, testimonials, credentials, statistics or quotes. Missing details become `[FILL: ...]`.
- **Useful first:** every post leaves the reader with something they can use or think about. One idea per post.
- **Subtle positioning:** authority comes from demonstrated knowledge and experience, never from stated intent. No begging for engagement, no hard selling. One call to action at most (`niche.call_to_action`), otherwise end with a genuine question.
- **Respect `niche.content_rules`, `niche.avoid_mentions` and `niche.banned_phrases`** at all times.

## 2. Discoverability
- **Hook:** the first 1–2 lines (under 200 characters) must stop the scroll on their own.
- **Keywords:** weave in `niche.keywords` naturally where they fit; never keyword-stuff.
- **Searchable framing:** answer questions the audience actually asks ("How do I…", "Why does…", "What should I know about…").
- **Hashtags:** LinkedIn 3–5 on the last line, Threads at most 1, Bluesky at most 2. Rotate from `niche.hashtags`; never repeat an identical set.

## 3. Short-post batches
- A batch is `data/batches/<name>/posts.json`; `python cli.py batch new` writes one. To write one by hand, each post needs `id`, `text`, `platforms` (e.g. `["linkedin"]`), `status: "draft"`, `pillar`, `facts_used`.
- Spread posts across the pillars and vary formats (tip, story, myth vs fact, list, opinion, question).
- Plain text only: LinkedIn shows markdown literally.

## 4. Carousels
- A deck is `data/carousels/<slug>.json`; slide types and fields are documented at the top of `brand_engine/carousel/render.py`. `data/carousels/example-deck.json` is a working reference.
- **Hero styles** (cover `photo_mode`): `"split"` (photo on top, text below), `"cutout"` (transparent PNG cutout over shapes; works with no photo), `"photo"` (full-bleed photo; falls back to `split` when the face would sit under the text).
- **Photos:** only the creator's own real photos from `assets/me/`. Never AI-generated likenesses of the creator and never photos of other people without permission. Rotate photos; don't reuse one in consecutive decks.
- **Themes** (`THEMES` in `render.py`): `violet` (default), `sky`, `cream`, `mint`, `ink`, `rose`, `tensor_dark`, `tensor_clean`, `tensor_editorial`. Never use the same theme in two consecutive decks.
- **No sales slides:** contact info and links belong in the caption, not on slides.
- Title fragments take a style (`dark`, `accent`, `hand`); inline `**bold**`, `==accent==`, `__handwritten__`, `` `code` ``.
- Render and look at the contact sheet in `assets/carousel/decks/<slug>/` before queuing.

## 5. Scheduling
- Slot times per platform: `config.yaml` -> `publish.queue.platform_times`, read in `config.yaml`'s `timezone`.
- Offset platforms that share a slot so one run doesn't process both at once.
- After queuing, run `python cli.py sync` so the cloud runner (`.github/workflows/post-queue.yml`) sees the queue.
- Secrets live only in `.env` (local) and GitHub Actions secrets. Never write a token into any other file.
